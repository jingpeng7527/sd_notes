4. share a file with other user
- add a shareList to Metadata
    (have to look up for one user requiring
    all the files shared with it)
- caching to speed up fetching the shareList
    (have a sharedFiles cache -> 
        k:userId, v:files;
    update the shareList and sharedFiles in 
    one transaction)
- a separate table; no need shareList in Metadata
    NoSQL: partitionKey:userId, sortKey:fileId
    SQL: (userId, fileId) composite primary key ^kmaLswbr


Ensure chunk in sync:
1. update based on client PATCH request
    after S3 return success for each chunk, 
    the client sends a PATCH request to server
    to update the status of the chunk
    (can't avoid bad user sending PATCH directly)
2. server-side chunk verification
    S3 return with a Etag, includes it in PATCH, 
    server verifies the status calling S3's ListParts API ^dmdwZ0Uy

fixed-size chuck:
